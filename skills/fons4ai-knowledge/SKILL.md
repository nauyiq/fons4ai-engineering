# 项目知识管理

目标是帮助人和 Agent 理解当前项目。根 README 与 AGENTS 统一导航；`docs/wiki/index.md` 就是项目地图，专题按问题组织；`docs/development/` 保留过程。取消默认卡片、分类矩阵和知识报告。

## 按当前操作加载

| 操作 | 读取 |
| --- | --- |
| 建立最小入口与知识基线 | [初始化](references/initialize.md) |
| 深化专题、摄入资料、沉淀已完成开发 | [更新与合并](references/consolidate.md) |
| 读取知识并回答问题 | [查询](references/query.md) |
| 检查过时、重复、冲突或断链 | [维护](references/maintain.md) |
| 生成或调整项目规则 | [规则提炼](references/derive-rules.md) |
| 涉及框架能力或无源码依赖 | [依赖能力核查](references/dependency-discovery.md)，再按语言加载 |

不要预读全部操作、语言参考和模板。专题模板仅在新建页面时读取。

## 共同边界

- 先检查本地资料，能查明的事实不问用户。只集中询问会改变范围、业务含义或规则的阻塞问题；推测标明，非阻塞缺口不阻止最小交付。
- 当前实现、预期行为、团队规范分开表达。代码与需求冲突时记录差异，不把缺陷合理化为规范。
- 仅沉淀有来源的长期结论。静态结构、接口签名、运行行为各自只能支持对应结论。
- 先更新已有页面；仅为独立阅读需求建页，不为每个事实、来源、查询或方法建页。保留人工内容和过程记录。
- 开发完成可自动更新本次受影响的已验证事实；不得自动升级偶然写法为全局规则，不扩展为全库重写。
- 通常不建立原始代码副本、向量库或外部工具依赖。没有源码时仍可核查已安装组件。

完成时简述更新页面、证据和未解决事项。无法核实的关键事实保留为待核实，不宣布已验证。用户只要求查询时不写文件。
