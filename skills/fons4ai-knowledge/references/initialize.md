# 初始化最小工程 Wiki

先看用户已有文档、构建清单、目录、入口、代表性调用和测试。辨识项目定位与能力边界，不先要求用户选择业务型/平台型分类。不运行代码来猜项目结构。

1. 初始化根目录 `README.md` 与 `AGENTS.md`：不存在则使用 [README 模板](../assets/templates/readme.md)、[AGENTS 模板](../assets/templates/agents.md) 创建；已存在则先读取，按当前授权合并修订相关内容，保留有效人工规则与项目说明，不整篇覆盖。已有大小写变体时复用该文件，避免重复入口。AGENTS 先介绍项目定位、实际技术栈和边界，再给出导航、技能使用方式与工作规则。README 面向使用者说明项目价值、能力、架构、业务/使用流程、关键交互和运行方式；创建或实质调整时读取 [README 创作参考](readme-authoring.md)。
2. 用 [项目地图模板](../assets/templates/wiki-index.md) 建立 `docs/wiki/index.md`。列出已发现能力、主要模块、代码/测试入口、相关专题；未知能力明确标注。
3. 根据 [规则提炼](derive-rules.md) 整理已有工程约定；没有证据时不生成假定的分层、工具或框架规则。
4. 只为当前理解项目必需的主题用 [专题模板](../assets/templates/topic.md) 建页。涉及结构、流程、交互、状态或数据关系时读取 [图解规则](diagram-guidance.md)，选择有助于理解的局部图；简单专题可只用文字或表格。无需预填所有领域、卡片、适配矩阵或 SQL 快照。
5. 初始化时遇到关键内部框架，先做小范围能力发现，读 [依赖核查](dependency-discovery.md)。不要全量解析所有依赖；未核实的组件列作候选，不写推荐 API。

涉及关键歧义，先做可完成的部分，将真正影响结论的问题集中询问。不要逐个确认名称、slug、文件名等可由仓库推导的事项。

模板是生成骨架，按当前项目事实填写并删除不适用提示；不要把本工具仓库的专属规则复制到业务项目。模板中的导航路径在目标文件中转换为实际相对链接，只链接已存在或本次创建的文件。开发记录、框架专题和技能路由尚不可用时不放断链或虚假入口。运行与验证命令集中维护在 README，AGENTS 引用，不重复维护两套。

README 必要的架构图、业务/能力流程图和关键时序图根据代码、配置、测试与已有资料绘制，区分三种图的表达目的。不能只输出文档目录和规则，也不能为凑图虚构调用链；简单项目按信息价值裁剪。只有复杂细节下沉 Wiki，README 保留足以理解项目的概览。

验证两个根文件存在、AGENTS 能先建立项目身份并指引技能使用、README 能帮助理解并开始使用项目；核对导航、图文与代码关系、命令来源和事实边界。无法核实的运行方式或交互明确指出缺口，不编造命令与图。初始化无需创建开发三件套或知识报告。业务文档缺失也不阻塞已有明确任务，先补与任务有关的最小入口。
