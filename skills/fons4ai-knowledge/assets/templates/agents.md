## 工作规则

1. 先理解再执行，关键需求不清楚时先澄清。
2. 需求分析、方案设计、任务规划是思考步骤，按复杂度决定是否生成文档。
3. 简单任务直接处理，复杂任务先设计，长期工作分阶段交付。
4. 优先复用项目已有结构、框架、组件、抽象、异常体系和编码约定。
5. 代码面向人类评审，保持可读性、合理抽象和必要的业务注释。
6. 结果必须可验证，不以编译成功代替行为验收。

涉及通用能力、准备新增公共封装/依赖或调用未知 API 时，先查已有调用、相关约定与实际依赖。无源码时继续检查组件包及公开接口，不根据名称猜测行为。

文档与代码冲突时区分当前实现、预期行为和待核实事项。不要把推测写成已完成事实，不将偶然实现升级为团队规则。
