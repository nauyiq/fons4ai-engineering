# 行为变化的 TDD

1. 从 AC 与现有测试确定本次行为及覆盖缺口，优先复用能够证明该缺口的失败测试/可执行复现。
2. RED：缺少覆盖时先新增或调整最小行为测试并运行，确认失败来自预期行为缺失，而不是语法、依赖或环境故障。
3. GREEN：实现满足行为的最小改动，保持项目结构、复用框架与现有封装。
4. REFACTOR：在测试保护下改善可读性与适度抽象，再运行受影响测试。

若检查发现行为已存在且测试覆盖充分，直接验证并说明，不人为破坏代码制造 RED。若无法执行测试，明确环境阻塞，不声称完成了 TDD。

单元测试适合纯逻辑；涉及数据库约束、序列化、框架配置或第三方关键语义，选择相应集成/契约测试。Mock 只隔离无关依赖，不能用自己设定的返回值证明真实组件行为。

先跑聚焦检查，再按调用关系和风险跑受影响回归。全量回归仅由项目门禁或具体风险触发；不要为每个切片机械重复全套测试。

只记录实际命令与关键结果；不要求逐条 RED/GREEN 证据表。已有失败仍可作为复现，但不能把无关的历史失败误认为本次 RED。
