# 完成检查

对照本次需求和实际 diff，而不是对照文件是否生成：

- AC 与边界行为是否通过适当验证，失败/未运行是否如实保留。
- 是否遵循目标模块结构、命名、异常/日志约定；注释是否解释业务原因。
- 是否重复实现现有框架能力、绕开有语义的包装层、无理由引入平行依赖；组件用法是否基于真实版本与行为证据。
- 是否有未授权范围扩大、无关变更或被覆盖的用户内容。

通过后更新任务状态与简短结果，依据 [更新与合并](../../fons4ai-knowledge/references/consolidate.md) 维护受影响长期知识。没有新知识不新增文件；未实现计划和未证实猜测不写成当前事实。已证实且有长期价值的缺陷可记为“已知问题/限制”，注明适用范围、预期差异及证据，不将其合理化为规范，也不写成已经修复。范围内未解决的缺陷仍影响验收，不能仅靠记录限制就标完成。

失败继续处理可解决问题；必须依赖用户或外部环境的阻塞具体说明。最终回复给出结果、验证和实质限制，不需要独立实施报告或机械交接协议。
