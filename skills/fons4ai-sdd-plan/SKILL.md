# SDD 规划

主 Agent 连续切换三个角色，不默认创建子 Agent。合并的是调用与交付次数，不省略需求分析和设计。一轮完整规划统一交付三份文档；阻塞性澄清可以跨轮进行。先读根规则、项目地图和相关代码，资源随阶段读取，不预读全部模板。

## 路由

1. 完整规划先读 [需求角色](references/requirements.md)，检查需求就绪度，即使用户已提供方案也不能跳过；有事实无需重复提问，有阻塞歧义先澄清。
2. 需求就绪后读 [设计角色](references/design.md)，完成业务落点、方案决策和本次适用详设，不能只把需求改写成技术摘要。
3. 关键设计明确后读 [任务角色](references/tasks.md)，按可验证交付切片组织任务，保留实施边界和完成条件。

仅补某个阶段时读取相应角色及其必要依据，引用真实已有资料或已确认的会话结论，不为模板补造前置文件。三者是思考步骤，简单明确、局部、可验证且无重大契约/数据/安全影响的任务不强制建文档，可以按已有授权直接执行。

正式需求在 `docs/development/features/YYYYMMDD-slug/` 保留 `需求说明书.md`、`技术设计.md`、`任务规划.md`。跨核心模块、公共契约、异步状态、数据结构或权限变化必须展开相应设计，不能因任务数少就当作简单任务。大型需求按可独立验收的能力分期，不引入 Task Pack 状态机。产物规则见 [产物约定](references/artifact-contract.md)。

检查 [风险提示](references/risk-checks.md) 中与当前工作相关的项，只有影响决策的风险进入文档。触及通用能力、准备新建封装或使用未核实 API 时，调用相邻项目知识管理技能的 [依赖核查](../fons4ai-knowledge/references/dependency-discovery.md)；无源码不构成跳过理由。

## 完成与授权

统一交付前执行 [规划完整性检查](references/planning-review.md)。正式 SDD 默认交付三份文档及关键决策后等待用户确认当前实施基线，不把“用 SDD 开发”或认可总体思路当作细化后规格已获批准。确认、显式免再次确认和同一基线续做均按 [实施授权](references/approval.md) 判断，通过后才进入 [实现技能](../fons4ai-sdd-implement/SKILL.md)。不逐角色索取批准，必要的关键澄清可提前集中进行。

只有规划授权时不执行实现。来源不足或需求冲突时继续不受影响的规划，明确具体缺口，不虚构基线。

本技能与 `fons4ai-knowledge`、`fons4ai-sdd-implement` 随套件分发；若缺少所需资源，说明缺项，不捏造其内容。
