# 执行或调查中发现预期需要调整

只在发现验收、设计或预期必须变化时读取；自身引入的局部缺陷留在实现闭环，不因此重新规划。先区分恢复原预期与改变预期，沿用当前授权范围，不把内部技能转接当作用户显式调用。

1. 查找受影响能力的 Wiki 或过程文档，并核实其适用性。有相关基线时，按复杂度进入 [变更](../../fons4ai-sdd-change/SKILL.md) 的轻量或正式分支。
2. 无相关基线且用户显式调用变更技能时，使用 [基线恢复](../../fons4ai-sdd-change/references/baseline.md)。其他技能自动转接不满足这个条件。
3. 无基线的自动路径：留在当前调查/规划中，从代码、测试、配置和用户说明核实当前行为、期望差异与来源。明确简单、局部、可逆且无重大影响的工作可在回复中说明依据，按授权进入 [实现](../../fons4ai-sdd-implement/SKILL.md)；行为变化仍需 TDD，不为调用变更技能而初始化 Wiki。
4. 复杂或重大变化依次使用 [需求](requirements.md)、[设计](design.md)、[任务](tasks.md) 角色及 [产物约定](artifact-contract.md) 形成此次完整规划，把已核实的当前情况和来源写入本次需求，不伪造旧需求。形成真实基线后，后续规格调整才能自动进入变更；本次规划完成按 [实施授权](approval.md) 评审当前基线，不能把原来的泛化开发意图当作新规格已获批准。仅要求单阶段时交付该阶段。

关键预期无法确定时集中澄清并继续无关工作；无相关既有能力则按新需求处理。已有资料不可靠时按未核实基线处理，不用文件存在冒充事实已确认。
