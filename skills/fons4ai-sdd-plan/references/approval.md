# 正式 SDD 的实施授权

适用于完整正式规划、正式规格变更和其实现入口；简单明确的直接工作沿用有效授权，不新增三件套审批。

## 判断授权对象

- 同意目标、总体思路或“使用 SDD 开发”表示启动该工作流，不自动表示已经评审随后细化的三份文档。
- 正式规划完成后，默认展示三份文档、关键决策、范围和待决点，等待用户确认当前实施基线后再改业务代码。生成文档、写入“已授权”、Agent 自己的计划或内部转接都不能产生授权。
- 用户明确要求“细化完成后直接实现，无需再确认”或等价指令时，可免再次确认，但仍需完成完整性检查，不得自行解决阻塞的业务歧义或扩大范围。
- 用户已确认当前三份文档/明确任务范围并授权执行，后续同一基线继续有效，不要求最新一条消息重复确认，也不逐角色、逐任务询问。
- SQL 执行、服务重启、单项方案选择等确认只覆盖相应事项，不扩大为整份实施方案获批。

## 最小记录与变化

在任务规划中集中记录：实施状态、对应的需求/设计版本或更新日期与任务范围、可定位的用户授权消息摘要（或显式免确认指令）。无授权则保持待评审，不预填“已确认”。无需独立审批报告、每个文档一份批准表或逐轮确认。

关键范围、业务口径、公共契约或高风险方案发生实质变化时，说明差异及影响并核对是否仍在授权内；超出原基线的部分重新评审，无关已授权工作可以继续。文字修正和已定方案内实现细节不使全部授权失效。

实施前还需通过 [规划完整性检查](planning-review.md)。授权不是正确性证明；资料缺少关键契约时先补设计，而不是依赖一句“已授权”开始猜测实现。
